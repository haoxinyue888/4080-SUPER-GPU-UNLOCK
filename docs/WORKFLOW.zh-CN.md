# 研究流程、日志与启动安全

对于希望研究类似适配的 RTX 4080 SUPER 用户，本文提供的是**研究与决策流程**，并非已经验证可在所有显卡上运行的 EFI 解锁教程。仓库中描述的实现只在**一张耕升 16 GB 显卡**上完成了相关实测。

**风险提示：** GPU 固件实验可能导致画面丢失、系统无法启动、数据丢失或硬件损坏。离线测试通过不等于获得真实硬件的安全认证。不要让 AI 自动执行会改变硬件状态的操作。

## 1. 研究原始资料并确认自己的硬件

- 阅读[原始研究项目](../REFERENCES.zh-CN.md)，区分 Ada GPU 研究、具体 Windows UEFI 移植方案及其他人的独立成功报告。
- 确定真实的 GPU 型号、厂商及板卡版本、显存配置、固件信息和 UEFI 环境。
- 从**只读检查**开始，记录确实在自己硬件上测得的证据。不要把别人的特定板卡配置当作默认值。
- 将自己的观测结果与上游实现的前提条件逐项比较。商品名称相同并不意味着内部配置相同。
- 如果必要的设备身份、固件、图形驱动所有权或显存布局信息未知，**停止，不要猜测**。

## 2. 先进行离线研究和模拟验证

- 明确哪些上游假设需要针对当前板卡调整，并正确注明原始 GPU 解锁机制的作者。
- 保留独立的设备身份验证、资源隔离与硬件恢复检查。
- 在考虑真实实验前，模拟**成功、拒绝继续、设备或启动程序缺失、图形所有权异常、日志写入失败及恢复失败**等情况。
- 模拟测试成功并不代表真实主板固件能够正常工作。不要为了让程序继续运行而关闭失败的安全检查。

## 3. 准备日志和恢复方案

我们的实验性 UEFI 应用每次启动都会生成一份新的、依次编号的 **`RUNnn/REPORT.TXT`**。每份报告记录阶段检查、关键读回值、是否实际尝试解锁、恢复证据及最终状态。已有报告不会被覆盖。

任何真实硬件实验前，应先确认：

- 日志可以可靠地写入并刷新到存储设备；日志写入失败时，应禁止开始实验。
- 原始、未修改的 Windows Boot Manager 可以独立启动。
- 存在已知可用的非实验性启动路径，并事先准备好恢复方案。
- 实验性 EFI 文件及依法自行取得的必要资源经过预期的指纹或校验值验证。
- 现场操作者理解：如果硬件操作后恢复失败，可能必须**按实体电源按钮关机**，而不是让软件自动重试。

**不要公开未经处理的原始报告。** 其中可能包含设备地址、设备路径及其他与主机有关的信息。与维护者或 AI 分享时，只提供人工审阅并脱敏后的内容。

### 如何解读日志

这些最终状态字段对我们尤其重要：

| 字段或观测项 | 含义 |
|---|---|
| `stage` | 验证或执行停止在哪个阶段 |
| `attempted=0` | GPU 解锁事务**尚未开始** |
| `driver_release=0` | UEFI 图形驱动的设备控制权**尚未释放** |
| `clean=1` | 程序报告其要求的清理条件已满足；**不等同于通用安全认证** |
| Windows 启动程序查找和预加载状态 | 在开始 GPU 操作之前，是否已经获得有效的 Windows 启动映像 |
| 恢复后的检查和交接状态 | 实验流程能否继续向 Windows 交接 |

固件成功标记或寄存器读回值**不能单独证明**计算性能提升；必须另外在 Windows 中进行基准测试。

## 4. 人工确认与不同的退出结果

**按 `U` 人工确认以及从 UEFI 交接到 Windows 的基本机制，已经存在于 TOTORONG 的上游实现中。** 我们保留了这个设计，并针对自己的硬件调整了验证与恢复流程。

| 情况 | 已观察或已实现的行为 |
|---|---|
| **尚未执行 GPU 操作时，未确认、按 Esc 或等待 30 秒超时** | 程序取消并将控制权返回 UEFI 固件，不开始 GPU 解锁事务。**不能保证 Windows 一定自动启动。** |
| **预检查拒绝继续** | 记录拒绝原因；使用者可以查看并返回固件。GPU 解锁事务不会开始。 |
| **经人工确认且成功的操作** | 必须通过 GPU、资源和图形恢复检查，之后才启动预先加载的 Windows Boot Manager。 |
| **图形驱动释放后或硬件操作后的状态不安全** | 程序会**停机等待**，不会猜测 Windows 是否还能安全启动。遵循实体恢复指令，不要自动重复实验。 |

**USB 优先启动并不等于无人值守自动解锁。** 即使 UEFI 先启动 USB，实际 GPU 实验仍须现场人工明确按下 `U`。应保留原始 Windows 启动项，不对其进行修改。

RUN06 在真实硬件上验证了**首次扫描成功发现 Windows 并完成交接**，但**没有触发**额外的延迟查找或存储设备连接回退路径；后者仅在主机模拟环境中通过测试。

## 5. 只测量相关效果，并明确不确定性

- 先记录未解锁时的稠密 GEMM 基线，实验后使用相同矩阵运算和计时方法进行比较。
- 解锁后的测量应重复进行，不只报告单次最高值。
- 将**固件事务进展、Windows 成功启动、计算性能提升**视为三项需要分别提供证据的结论。
- 记录普通重启后的表现。我们的显卡在未再次运行 USB 解锁流程的重启后，吞吐量回到了接近原始水平。
- 对未测试板卡、跨重启可靠性、长期稳定性及实际应用收益，明确标注为**尚未验证**。
